Create Assets with SKU Properties API

Bulk-creates image assets for one or more barcodes and optionally merges caller-supplied skuProperties into each SKU’s patternDict. Extension of POST /api/v1/asset/create that propagates property updates to the SKU, all existing assets for that barcode, and newly created assets.

Base URL

/api/v1/asset

Authentication

None. This is an internal service endpoint (same as POST /api/v1/asset/create).

Create assets with optional SKU properties

Resolves SKUs by barcode, merges skuProperties into patternDict when provided, creates one asset per image, and returns per-barcode success/failure results.

Request

POST /api/v1/asset/createWithProperties

Content-Type: application/json

Request body

Field Type Required Default Description
clientName string Yes — Client code (e.g. TEST, FLIXSTOCK). Used for SKU lookup, asset scoping, and filter sync.
createWithoutCSVData boolean No false When false, missing SKUs require ingested CSV data (SkuCsv) before a SKU can be created. When true, SKUs are created with an empty patternDict if no CSV exists.
files array Yes — Min length 1. One entry per barcode to process.
files[].barcode string Yes — Product barcode (trimmed). Must be unique within the request for SKU resolution.
files[].skuProperties object No — Arbitrary key-value pairs merged into the SKU’s existing patternDict (shallow merge). Omitted or empty object → behaves like /create.
files[].images array Yes — Min length 1. One asset is created per image.
files[].images[].name string No — Display name. Defaults to the filename portion of imagePath.key on save.
files[].images[].imagePath object Yes — S3 location of the uploaded image.
files[].images[].imagePath.key string Yes — S3 object key (from pre-signed upload flow).
files[].images[].imagePath.host string Yes — S3 bucket name (e.g. metamodels-ai).
files[].images[].characteristics object No — Optional metadata stored on the image subdocument.

Typical workflow

  1. Upload images to S3 — GET /api/v1/asset/getUploadUrl?fileName={name}&clientName={client} returns { key, url }. PUT the file to url.
  2. Create assets — Call this endpoint with the returned key and bucket host in each imagePath.
  3. Optional properties — Include skuProperties on any file entry to merge fields into patternDict before assets are created.

Success response — 200 OK

Always returns HTTP 200 when the handler completes. Individual barcodes may succeed or fail inside data. 

{
    "data": [
        {
            "barcode": "8721222146063",
            "success": true,
            "assets": [
                {
                    "_id": "665f1a2b3c4d5e6f7a8b9c0d",
                    "patternDict": {
                        "fabric": "cotton",
                        "color": "blue"
                    },
                    "existed": false
                }
            ]
        },
        {
            "barcode": "9999999999999",
            "success": false,
            "error": "SKU 9999999999999 has no CSV data. Set createWithoutCSVData to true to bypass."
        }
    ]
}

Response fields

Field Type Description
data array One result object per entry in files, in request order.
data[].barcode string Barcode from the request.
data[].success boolean true if assets were created/resolved and the SKU is not shouldNotProduce.
data[].assets array Present when success is true. One item per image in files[].images.
data[].assets[]._id string MongoDB ObjectId of the asset document.
data[].assets[].patternDict object Merged patternDict used for this asset (after skuProperties merge when applicable).
data[].assets[].existed boolean true if an active asset already existed for the same SKU + imagePath.host + imagePath.key; false if newly created.
data[].error string Present when success is false. Human-readable failure reason for that barcode.

Processing behavior

SKU resolution (resolveSkus)

  1. Loads existing SKUs for all unique barcodes + clientName.
  2. For barcodes with no SKU:
    • Looks up SkuCsv for CSV data.
    • If createWithoutCSVData is false and no CSV data exists → barcode gets { error: "SKU {barcode} has no CSV data..." } (no SKU created).
    • Otherwise creates a new SKU with patternDict from CSV csvData (or {} when bypassing).
  3. Emits filter-update for SKUs with a non-empty patternDict that are not yet filtersSynced.

skuProperties merge (mergeAndPropagatePatternDict)

When at least one file includes skuProperties:

  1. For each such barcode, shallow-merges skuProperties onto the existing patternDict: { ...existing, ...skuProperties }.
  2. Updates the SKU document: sets patternDict, filtersSynced: false, embeddingDone: false.
  3. Updates all existing assets for that barcode + clientName with the merged patternDict.
  4. New assets created in the same request use the merged patternDict.

Files without skuProperties use the SKU’s current patternDict (unchanged unless another file in the same batch updated the same barcode — merge runs on all skuProperties entries first).

Asset creation (createAsset)

  • One asset per image; uniqueness is enforced on active rows: (skuId, image.imagePath.host, image.imagePath.key).
  • Duplicate image for the same SKU returns the existing asset with existed: true (no duplicate insert).
  • Assets are created in batches of 10 concurrent createAsset calls per barcode.
  • On save, Image pre-save hook generates thumbnail paths and emits thumbnail-generation-init.

shouldNotProduce SKUs

If the SKU has shouldNotProduce: true:

  • Assets are still persisted (for traceability).
  • The barcode result is success: false with error SKU {barcode} is marked shouldNotProduce.
  • patternDict / assets are not returned to the caller for that barcode.

Post-create side effects

  • bumpIngestionSchedule — For SKUs that received at least one newly created asset (existed: false), sets ingestionScheduledAt on the SKU (debounced 5 minutes) to trigger re-embedding when appropriate.
  • filter-update event — Fired during SKU resolution when patternDict is non-empty and filters need syncing.

Error responses

Validation — 400 Bad Request

Returned by celebrate/Joi when the body fails schema validation:

{
    "message": {
        "body": [
            "\"clientName\" is required",
            "\"files\" must contain at least 1 items"
        ]
    }
}
Condition Joi message (approx.)
Missing clientName "clientName" is required
Missing or empty files "files" is required / must contain at least 1 items
Missing barcode on a file "barcode" is required
Missing or empty images "images" is required / must contain at least 1 items
Missing imagePath.key or imagePath.host "imagePath.key" is required etc.

Per-barcode failures (inside 200 response)

error value Cause
SKU {barcode} has no CSV data. Set createWithoutCSVData to true to bypass. No SKU and no CSV when createWithoutCSVData is false.
SKU not found for barcode {barcode} SKU missing from map after resolution (unexpected).
SKU {barcode} is marked shouldNotProduce SKU flagged shouldNotProduce in CSV/SKU record.
{err.message} Uncaught exception while processing that file (e.g. DB error).

Server error — 500 Internal Server Error

Unhandled errors in the outer try/catch (e.g. bulk write failure before per-file loop):

{ "message": "..." }

Comparison with POST /api/v1/asset/create

Aspect /create /createWithProperties
Request shape Same (clientName, createWithoutCSVData, files[]) Same + optional files[].skuProperties
patternDict on new assets SKU’s current patternDict Merged patternDict when skuProperties provided
SKU / existing asset updates No Yes — merges into SKU and all assets for barcode
filtersSynced / embeddingDone Unchanged Set to false when properties merged
Response shape Identical Identical
Batch size 10 assets per barcode 10 assets per barcode

Use /createWithProperties when ingesting assets and updating searchable/filterable SKU metadata in one call. Use /create when patternDict is already correct on the SKU.

Indexes relevant to this API

  • Unique active asset per (skuId, image.imagePath.host, image.imagePath.key)
  • (barcode, clientName) for asset updates during property merge
  • Wildcard patternDict.$** for filter/search queries

Notes

  • Request body limit: 50 MB (body-parser on /api/v1).
  • CORS: * origin; methods include POST.
  • Partial success is normal: one failed barcode does not roll back others.
  • skuProperties keys are not validated — any JSON object is accepted and stored in patternDict.
