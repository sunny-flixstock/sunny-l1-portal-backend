Partner Framework Fetch API

Read-only endpoint for external integrations to resolve the active production framework for a client and optional constraint dimensions.

Base URL

GET /api/v1/partner/framework

Authentication

All requests require a valid partner API key in the x-api-key header.

Header Required Description
x-api-key Yes Partner API key from PARTNER_API_KEYS

401 Unauthorized

Returned when the API key is missing or invalid.

{ "message": "Invalid or missing API key" }

Fetch active production framework

Resolves the best-matching framework group for the given client and optional constraints, then returns the group's active production framework version together with knowledge fields, framework vocab, and category registry.

Query parameters

Parameter Type Required Description
client string Yes Client code (e.g. CLIENT_A)
gender string No Gender constraint used during framework group resolution
season string No Season constraint used during framework group resolution
category string No Category constraint used during framework group resolution

Framework group resolution

Groups are matched using the following rules:

  • Only groups for the requested client are considered.
  • A group with a null value for gender, season, or category acts as a wildcard for that dimension.
  • If a group constrains a dimension (non-null), the request must include the same value for that dimension or the group does not match.
  • Among matching groups, the one with the highest specificity wins (more constrained dimensions = more specific).
  • If specificity is tied, the group with the higher priority wins.
Example: A request with client=CLIENT_A&gender=women&season=ss26 can match a group scoped to women + ss26, or a less-specific group with wildcards such as gender=women only, or a client-wide default group with all dimensions null.

Example request

GET /api/v1/partner/framework?client=CLIENT_A&gender=women&season=ss26&category=dresses HTTP/1.1
x-api-key: your-partner-api-key

Response fields

Field Description
data.frameworkGroup The resolved framework group metadata
data.frameworkVersion The group's activeProductionFrameworkVersionId document (metadata only)
data.knowledgeFields Per-domain S3 storage objects for generated framework knowledge markdown. Each entry includes a signed CloudFront CDN URL on url.
data.frameworkVocab Full framework vocab document, including the vocab payload
data.categoryRegistry Full category registry document, including the registry payload

Error responses

Status Condition
400 Missing client query parameter (Joi validation error)
400 { "message": "Client not found: UNKNOWN_CLIENT" }
400 { "message": "No framework group found for client \"CLIENT_A\" with the given constraints" }
400 { "message": "No active production framework version for framework group: ..." }
400 Active production framework version, vocab, or registry document not found
401 Invalid or missing x-api-key header

Notes

  • Knowledge field url values are signed CloudFront URLs generated at request time from the stored S3 bucket and key. URLs expire per CloudFront signer configuration (default: 2 days).
  • New knowledge field uploads also persist CloudFront URLs (not raw S3 URLs) when framework domain outputs are saved.
  • This endpoint is separate from the internal /api/v1/framework-group and /api/v1/framework-version CRUD APIs and is intended for partner / front-office integrations only.
  • VS Code REST Client examples are available in test/partnerFramework.http.
